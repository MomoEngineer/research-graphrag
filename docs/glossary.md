# Glossar

Zentrale Fachbegriffe dieses Repositories. Etablierte englische Fachbegriffe bleiben unübersetzt (siehe [documentation-standards.md](documentation-standards.md)). Bei Erweiterungen der Domäne wird dieses Glossar mitgepflegt.

| Begriff | Bedeutung |
| --- | --- |
| **GraphRAG** | Retrieval-Augmented Generation über einem aus dem Korpus gebauten Wissensgraphen (Entitäten, Beziehungen, Communities, Community-Reports). |
| **MCP (Model Context Protocol)** | Offenes Protokoll, über das Tools/Resources/Prompts standardisiert für LLM-Clients (z. B. GitHub Copilot) bereitstehen. |
| **MCP-Server** | Prozess, der zusammengehörige MCP-Fähigkeiten bündelt und über einen Transport (hier `stdio`) bereitstellt. research-graphrag hat **einen** Server. |
| **MCP-Tool** | Aufrufbare Fähigkeit mit definiertem Input-/Output-Schema (z. B. `search_local`, `get_paper`). |
| **Transport `stdio`** | Standard-Transport: VS Code startet den Server als lokalen Unterprozess, Kommunikation über Standard-Input/Output, kein Netzwerk. |
| **LLM-Bridge / MCP-Sampling** | Der Server bindet **kein** Modell; benötigte Completions werden zur Abfragezeit per `session.create_message` vom Client (Copilot) angefordert (siehe [ADR 0004](adr/0004-llm-bridge-via-mcp-sampling.md)). **Implementiert** in Phase 7 / A1: injizierbarer Generierungs-Port (`generation/`), genutzt vom Tool `answer_question` mit `synthesize = true`; ohne Sampling degradiert die Antwort sichtbar zu `generated = false` ([ADR 0012](adr/0012-llm-bridge-and-answer-synthesis-phase7.md)). |
| **Local / Global / DRIFT / Basic Search** | GraphRAG-Suchmodi: Detail an Entitäten (Local), corpusweit über Community-Reports (Global), global + lokal verfeinert (DRIFT), Top-k-Vektorsuche auf Chunks (Basic). Im Offline-Hybrid **implementiert** (Phase 4): Basic = TF-IDF-Top-k, Local = Seeds + Chunk-Nachbarschaft + Paper-Fan-out, Global = Query→Community-Ranking, DRIFT = Global→Local-Hybrid ([ADR 0008](adr/0008-retrieval-and-query-router-phase4.md), [ADR 0021](adr/0021-local-multi-seed-phase10.md)). |
| **Seed (Local Search)** | Anker-Chunk der Local Search. Seit Phase 10 / V1 sind es die **Top-5** der Chunk-Wertung statt eines einzigen; ihre Chunk-Nachbarschaften werden per Rang-Fusion zusammengeführt, der Paper-Fan-out folgt dem **ersten** Seed (Ankerpaper) ([ADR 0021](adr/0021-local-multi-seed-phase10.md)). Nicht zu verwechseln mit dem **Seed-Paper** des Online-Modus oder dem Zufalls-Seed der Community-Detection. |
| **Community-Report** | Von GraphRAG erzeugte Zusammenfassung einer Graph-Community; Grundlage der Global Search. Im Offline-Hybrid **extraktiv** erzeugt (repräsentative Paper + Top-TF-IDF-Keywords), LLM-Veredelung optional zur Abfragezeit ([ADR 0007](adr/0007-graphrag-index-phase3-option-b.md)). |
| **Leiden** | Community-Detection-Algorithmus. Offline nicht verfügbar (`leidenalg`/`igraph` fehlen); der Offline-Hybrid nutzt **Louvain** (`networkx`). |
| **Louvain** | Community-Detection über `networkx`; Ersatz für Leiden im Offline-Hybrid ([ADR 0005](adr/0005-graphrag-index-backend-open.md)). |
| **Canonical Paper JSON** | Kanonisches Zwischenformat je Paper (Schema 0.4.0): heuristische Section-Hierarchie, Chunk-IDs, Referenz-Abschnitt, DOI/arXiv-Identifikatoren, Seiten-Range/Section-Provenienz, Qualitätsflags; der Seitentext ist normalisiert ([ADR 0015](adr/0015-noise-reduction-keywords-and-sections-phase7.md)). Bounding-Box-Provenienz ist zurückgestellt ([ADR 0006](adr/0006-canonical-model-phase2-scope.md)). |
| **Chunk / TextUnit** | Kleinste retrievbare Texteinheit mit Provenienz; abschnitts-/größenbasiert gebildet. Die Seite ist **keine** Chunk-Grenze, sondern eine Provenienz-Range `page_number`…`page_end` ([ADR 0013](adr/0013-chunking-refinement-phase7.md)). |
| **Section-Absorption** | Deterministische Rückführung inhaltsarmer Abschnitte in ihren Vorgänger; wirkt gegen die Übersegmentierung der Überschriften-Heuristik (`front`/`abstract`/`references` bleiben geschützt, [ADR 0013](adr/0013-chunking-refinement-phase7.md)). |
| **Textnormalisierung** | Reparatur typografischer Ligaturen (`conﬁguration` → `configuration`) und Entfernen nicht dekodierbarer `/uniXXXXXXXX`-Glyphen im Seitentext – **vor** Struktur-Analyse und Chunking. Bewusst kein pauschales NFKC, das die Pseudocode-Reject-Regel aushöhlen würde ([ADR 0015](adr/0015-noise-reduction-keywords-and-sections-phase7.md)). |
| **Keyword-Politik** | Kuratierte Domänen-Stopwords und Token-Filter für **extraktive Keyword-Listen** (Community-Keywords, Übersicht-Entwürfe). Wirkt als **Nachfilter vor dem Anschnitt** – der Vektorraum des Ähnlichkeitsgraphen und das Retrieval bleiben unberührt ([ADR 0015](adr/0015-noise-reduction-keywords-and-sections-phase7.md)). |
| **Qualitäts-Gate / -Flag** | Heuristisches Signal der Extraktion (z. B. `missing_abstract`, `ocr_noise`, aggregiert `short_chunks:<n>`); gesammelt im `data/quality_report.*` ([ADR 0006](adr/0006-canonical-model-phase2-scope.md), [ADR 0013](adr/0013-chunking-refinement-phase7.md)). |
| **Provenienz** | Herkunftsnachweis einer abgeleiteten Aussage: Paper-ID, Abschnitt, Seite/Chunk (ggf. Bounding-Box), Score (siehe [documentation-standards.md](documentation-standards.md), Abschnitt 5). |
| **Docling / Marker** | PDF-Extraktoren (Docling pure Python, Marker für formel-/layoutlastige PDFs). Offline **nicht beschaffbar**; der Offline-Hybrid nutzt `pypdf` (Text). Docling/Marker sind späterer Ausbau ([ADR 0005](adr/0005-graphrag-index-backend-open.md)). |
| **LanceDB / Parquet** | Eingebetteter Vektor-/Spaltenspeicher der MS-GraphRAG-Artefakte. Offline **nicht beschaffbar**; der Offline-Hybrid nutzt **SQLite** (stdlib) + TF-IDF-Matrix ([ADR 0005](adr/0005-graphrag-index-backend-open.md)). |
| **manifest.json / Dedup** | Datei-Hash → Paper-ID; unveränderte PDFs werden bei der Ingestion übersprungen. |
| **Intake** | Vorgelagerte Prüfung des Eingangsordners `new_papers/`: sha256 → DOI/arXiv → Titel-Ähnlichkeit, mit **abgestufter** Konsequenz (nur der bitgenaue Treffer löscht). |
| **Quarantäne** | `new_papers/_duplikate/` – Ablage für Identifikator-Duplikate: aus dem Eingang entfernt, aber umkehrbar statt gelöscht. |
| **Online-Modus** | Separat startbare Kandidatensuche (`python -m scripts.discover`): fragt arXiv und OpenAlex zu einer Anfrage **aus dem eigenen Bestand**, dedupliziert mit der Intake-Logik und schreibt einen append-only Bericht. Lädt **keine** Volltexte und ist bewusst kein MCP-Werkzeug ([ADR 0020](adr/0020-online-candidate-search-phase9.md)). |
| **Kandidat** | Ein Vorschlag auf **Metadatenebene** (Titel, Jahr, Identifikator, Abstract, Verweis) samt Begründung, aus welcher Anfrage er stammt. Ein Kandidat ist kein Bestand – der Weg in den Korpus führt über `new_papers/` und den Intake. |
| **Transport-Port** | Das Protocol `HttpClient`: die einzige Stelle, an der eine Netzverbindung entsteht. Weil alles Übrige gegen den Port arbeitet, bleibt der Online-Modus bis auf den Transport offline testbar – dasselbe Muster wie beim Generierungs-Port ([ADR 0004](adr/0004-llm-bridge-via-mcp-sampling.md)). |
| **TF-IDF** | Deterministisches Gewichtungsverfahren des Offline-Hybrid (`scikit-learn`); Grundlage der Chunk-Ähnlichkeit, des Paper-Graphen und des Community-Rankings ([ADR 0005](adr/0005-graphrag-index-backend-open.md)). |
| **BM25** | Probabilistisches Rankingmodell mit Term-Sättigung (`k1`) und Längennormalisierung (`b`), handimplementiert über denselben Token-Raum wie TF-IDF ([ADR 0014](adr/0014-hybrid-retrieval-bm25-tfidf-phase7.md)). |
| **Hybrid-Wertung / RRF** | Standard-Wertung der Chunk-Modi: Die Ranglisten von BM25 und TF-IDF werden per **Reciprocal Rank Fusion** verbunden (`1/(K+Rang)`, `K = 60`). `score` ist dann ein Fusionswert – **keine** Ähnlichkeit; `score_tfidf`/`score_bm25` weisen die Beiträge aus. Umschaltbar über `--scoring` ([ADR 0014](adr/0014-hybrid-retrieval-bm25-tfidf-phase7.md)). |
| **Gold-Set / Hit@k / MRR** | Versioniertes Fragenset mit **mechanisch aus dem Chunk-Text abgeleiteten** Labels (`eval/retrieval-gold.json`) und die darauf berechneten Kennzahlen (`python -m scripts.eval_retrieval`) – Messbasis für Retrieval-Änderungen ([ADR 0014](adr/0014-hybrid-retrieval-bm25-tfidf-phase7.md)). |
| **Coverage / Selektivität / Lift** | Kennzahlen der Community-Auswahl: Anteil der erwarteten Paper in den Top-n-Communities, Anteil des dabei betrachteten Korpus und ihr Quotient. Nur der **Lift** ist vergleichbar – triviale Strategien („größte Communities") erreichen hohe Coverage bei ebenso hoher Selektivität und landen bei ≈ 1,0 ([ADR 0016](adr/0016-quantitative-retrieval-evaluation-phase7.md)). |
| **Deckelung (Ceiling)** | Diagnose für Global/DRIFT: Enthält die gewählte Community überhaupt ein erwartetes Paper? Trennt **Auswahlfehler** (`no_community`, `community_missed`) von Rankingfehlern innerhalb der Community ([ADR 0016](adr/0016-quantitative-retrieval-evaluation-phase7.md)). |
| **Retrieval-Baseline / Regressions-Check** | Eingefrorene Ränge je Frage und Ebene (`eval/retrieval-baseline.json`). `--check` meldet **qid-genau**: `Treffer → kein Treffer` ist eine Regression (Exit 1), Rangbewegung nur ein Bericht; ein **Fingerprint-Guard** lehnt den Vergleich ab, sobald Korpus oder Parameter nicht mehr passen (Exit 2) ([ADR 0016](adr/0016-quantitative-retrieval-evaluation-phase7.md)). |
| **Query-Router** | Leichtgewichtige Auswahl des passenden Suchmodus je Fragetyp (Phase 4), gehärtet in Phase 7 / A7: Signale mit **deklarierter Match-Art** (Wortgrenze/Wortanfang für Englisch, Teilwort nur für deutsche Stämme), `basic` als Rückfallebene, **Konfidenzstufe** (`strong`/`weak`/`none`) und ausgewiesene Signale statt stiller Entscheidung ([ADR 0017](adr/0017-router-hardening-phase7.md)). |
| **Contract-Treue (Router)** | Anteil der Fragen, deren gerouteter Modus in der Modus-Menge liegt, die die README-Tabelle „Fragetypen → Suchmodus" für ihren Fragetyp vorsieht. Steuerndes Maß der Router-Messung; die Retrieval-Kennzahlen dienen nur als **Veto** gegen Verschlechterung ([ADR 0017](adr/0017-router-hardening-phase7.md)). |
| **Zitationsgraph (`CITES`)** | Gerichtete Kanten zwischen Papern **des eigenen Korpus**, erkannt über DOI-/arXiv-/Titel-Treffer im Referenzabschnitt (Präzedenz `doi` > `arxiv` > `title`, Präzision vor Recall). Additiv in `index.sqlite` (`citation_edges`), abfragbar über `get_citations` bzw. `python -m scripts.citations`; externe Referenzen bleiben Zielbild ([ADR 0011](adr/0011-intra-corpus-citation-graph-phase7.md)). |
| **ADR (Architecture Decision Record)** | Dokumentierte Architektur-/Grundsatzentscheidung mit Kontext, Entscheidung und Konsequenzen (siehe [adr/README.md](adr/README.md)). |
| **Definition of Done (DoD)** | Verbindliche Checkliste, ab wann ein Beitrag/Server als fertig gilt (siehe [repository-structure.md](repository-structure.md)). |
| **Reproduzierbarkeit** | Wiederholbarkeit von Ergebnissen durch fixierte Versionen (Lockfile), Seeds und Lauf-Metadaten. |
| **Offline-Firmenumfeld** | Entwicklungsumfeld ohne PyPI-Zugang; prägt die Tooling-Kompromisse (siehe [ADR 0002](adr/0002-venv-and-offline-dependency-strategy.md), [ADR 0003](adr/0003-offline-test-and-coverage-tooling.md)). |
| **SRQ (Sub-Forschungsfrage)** | Zuordnungsdimension der kuratierten `Übersicht.md`. |
