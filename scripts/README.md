# scripts/

Entwickler-Hilfsskripte (kein MCP-Server). Aufruf stets über `python -m scripts.<name>`
vom Repository-Wurzelverzeichnis (WinPython-Konsolenskripte liegen nicht im `PATH`).

| Skript | Zweck |
| --- | --- |
| `coverage_offline.py` | Offline-Coverage-Gate: Zeilenabdeckung je Kernmodul via stdlib `trace` ([ADR 0003](../docs/adr/0003-offline-test-and-coverage-tooling.md)). Aufruf: `python -m scripts.coverage_offline`. |
| `ingest.py` | Drop-in-Ingestion: `papers/*.pdf` → Canonical JSON → TF-IDF/SQLite-Index **+ Paper-Ähnlichkeitsgraph mit Louvain-Communities** (Option B, [ADR 0007](../docs/adr/0007-graphrag-index-phase3-option-b.md)) **+ Intra-Korpus-Zitationsgraph** ([ADR 0011](../docs/adr/0011-intra-corpus-citation-graph-phase7.md)) **+ zitierfähige Metadaten** aus Übersicht und `metadata/paper_metadata.json` ([ADR 0025](../docs/adr/0025-citable-paper-metadata.md)). Aufruf: `python -m scripts.ingest`. |
| `intake.py` | Korpus-Zufluss: prüft `new_papers/*.pdf` in drei Stufen auf Doppelbestand (sha256 → DOI/arXiv → Titel-Verdacht), übernimmt Neues nach `papers/` und stoßt **einen** Ingest-Lauf an ([ADR 0019](../docs/adr/0019-corpus-intake-new-papers-phase8.md)). **Nur der sha256-Treffer löscht**; Identifikator-Treffer wandern nach `new_papers/_duplikate/`. `Übersicht.md` ist seit Phase 15 / G4 außer Dienst und bekommt **keine** neue Zeile mehr ([ADR 0034](../docs/adr/0034-decommission-uebersicht-and-inflow-stop-rule-phase15.md)). Aufruf: `python -m scripts.intake [--dry-run] [--delete-identifier-duplicates]`. |
| `ask.py` | Frage über die Retrieval-Modi (Basic/Local/Global/DRIFT) mit Provenienz beantworten; `--mode auto` routet heuristisch und zeigt dabei Modus, **Konfidenzstufe** und die auslösenden Signale ([ADR 0008](../docs/adr/0008-retrieval-and-query-router-phase4.md), [ADR 0017](../docs/adr/0017-router-hardening-phase7.md)); `--synthese` bereitet die Belege nummeriert über die LLM-Bridge auf (CLI ohne Modell → sichtbarer Noop-Fallback, [ADR 0012](../docs/adr/0012-llm-bridge-and-answer-synthesis-phase7.md)); `--scoring` wählt die Wertung `hybrid`/`tfidf`/`bm25` ([ADR 0014](../docs/adr/0014-hybrid-retrieval-bm25-tfidf-phase7.md)); `--seeds` setzt die Zahl der Anker-Chunks der Local Search ([ADR 0021](../docs/adr/0021-local-multi-seed-phase10.md)). Aufruf: `python -m scripts.ask "<Frage>" [--mode …] [--scoring …] [--seeds …] [--synthese]`. |
| `graph_info.py` | Read-only-Übersicht der Graph-Communities (Keywords, Vertreter, Auszug); Phase-3-Nachweis ([ADR 0007](../docs/adr/0007-graphrag-index-phase3-option-b.md)). Aufruf: `python -m scripts.graph_info`. |
| `citations.py` | Read-only-Übersicht der Intra-Korpus-Zitationen eines Papers (`cites`/`cited_by` mit Quelle und Match-Kriterium doi/arxiv/title, [ADR 0011](../docs/adr/0011-intra-corpus-citation-graph-phase7.md)). Aufruf: `python -m scripts.citations <paper_id>`. |
| `cite.py` | Read-only-**Literaturangabe** eines Papers in **Harvard** und **APA** samt Kurzbeleg, Herkunft je Feld und Konfidenz; fehlende Pflichtfelder werden benannt statt geraten ([ADR 0025](../docs/adr/0025-citable-paper-metadata.md)). Aufruf: `python -m scripts.cite <paper_id> [--stil harvard\|apa]`. |
| `resolve_metadata.py` | **Separat startbare** Online-Auflösung der Zitationsdaten (Autoren, Venue, Publikationsjahrgang) über OpenAlex mit arXiv als Rückfall; schreibt nach `metadata/paper_metadata.json` und protokolliert append-only nach `data/metadata_log.md`. Übernommen wird **automatisch**, ein nicht eindeutiger Beleg trägt sichtbar `weak` ([ADR 0026](../docs/adr/0026-online-metadata-resolution.md)). Benötigt Netz (`RESEARCH_GRAPHRAG_PROXY` oder `--proxy`). Aufruf: `python -m scripts.resolve_metadata [--dry-run] [--limit N] [--paper <id>] [--alle]`. |
| `discover.py` | **Separat startbare** Online-Kandidatensuche auf Metadatenebene (arXiv + OpenAlex): Die Anfrage entsteht aus dem eigenen Bestand (`--community` bzw. `--seed`), Treffer werden quellenübergreifend zusammengeführt und mit der **Intake-Logik** gegen den Korpus dedupliziert; das Ergebnis wird append-only an `data/online_candidates.md` angehängt ([ADR 0020](../docs/adr/0020-online-candidate-search-phase9.md)). Mit dem opt-in Flag `--download` lädt der Lauf zusätzlich frei lizenzierte Volltexte (CC0/CC-BY/CC-BY-SA, nur aus OpenAlex) nach `new_papers/`, sofern der Inhalt den Titel-Rückvergleich besteht – alles andere bleibt ein Link ([ADR 0035](../docs/adr/0035-fulltext-download-phase9-s2.md)). **Kein MCP-Werkzeug.** Führt der Weg nach außen über einen Proxy, wird er über `RESEARCH_GRAPHRAG_PROXY=host:port` oder `--proxy` angegeben. `--dry-run` zeigt vorab nur die gebildeten Anfragen – ohne Abfrage und ohne Bericht. Aufruf: `python -m scripts.discover --community <id> [--seed <paper_id>] [--seit JAHR] [--limit N] [--download] [--eingang <Pfad>] [--dry-run]`. |
| `resolve_references.py` | **Separat startbare** Erzeugung von **Referenz-Einträgen ohne Volltext**: liest die kuratierte Kennungsliste `new_papers/referenzen.txt` (DOI/arXiv, `#` leitet Kommentare ein), löst jede Kennung über OpenAlex mit dem arXiv-Feed als Rückfall **und** Abstract-Quelle auf und legt je Kennung eine Stub-Datei `*.refjson` im Eingangsordner ab; protokolliert append-only nach `data/references_log.md` ([ADR 0029](../docs/adr/0029-reference-stub-resolution-phase13.md)). **Kein Volltext-Download, kein MCP-Werkzeug.** Vor jeder Abfrage wird gegen Korpus, vorhandene Stub-Dateien und `new_papers/_duplikate/` geprüft – ein zweiter Lauf ist folgenlos; die Liste bleibt unverändert. Ohne Titel entsteht **keine** Datei, ohne Abstract entsteht sie mit einem Hinweis zum manuellen Nachtrag. Benötigt Netz (`RESEARCH_GRAPHRAG_PROXY` oder `--proxy`). Aufruf: `python -m scripts.resolve_references [--dry-run] [--limit N] [--liste <Pfad>]`. |
| `update_overview.py` | **Seit Phase 15 / G4 außer Dienst:** verweigert den Lauf standardmäßig (Exit 1, Hinweis auf `metadata/curation.json`); nur mit dem ausdrücklichen `--force` hängt es weiterhin deterministische, extraktive Entwurfszeilen **append-only** an `Übersicht.md` an (byte-erhaltend, atomar, ID-Reihe `Z1`, `Z2`, …, [ADR 0019](../docs/adr/0019-corpus-intake-new-papers-phase8.md), [ADR 0034](../docs/adr/0034-decommission-uebersicht-and-inflow-stop-rule-phase15.md)). Aufruf: `python -m scripts.update_overview [--force]`. |
| `migrate_curation.py` | **Phase 15 / G4:** überführt das kuratierte Relevanzurteil (`Themenfokus`, `Relevanz fuer Expose`, `SRQ-Zuordnung`) aus `Übersicht.md` **verlustfrei** nach `metadata/curation.json`, geschlüsselt über `paper_id` ([ADR 0034](../docs/adr/0034-decommission-uebersicht-and-inflow-stop-rule-phase15.md)). `--dry-run` zählt nur, `--check` vergleicht eine bestehende Datei Zeile für Zeile gegen `Übersicht.md` (Exit 1 bei Abweichung). Aufruf: `python -m scripts.migrate_curation [--dry-run] [--check]`. |
| `status.py` | Read-only-Status von Index/Korpus (Schema, Paper/Chunks/Communities/Zitationskanten, Qualitäts-Flags, Identifier-Abdeckung sowie seit Phase 12 die **Zitierfähigkeit** und die Zahl schwach belegter Datensätze) + Konsistenz-Check `papers/ ↔ manifest ↔ canonical`; pragmatische QS ([ADR 0010](../docs/adr/0010-drop-in-workflow-and-qa-phase6.md)). Aufruf: `python -m scripts.status`. |
| `backup.py` | Sicherung des **nicht reproduzierbaren** Bestandes in ein Verzeichnis außerhalb der Arbeitskopie: PDF-Korpus, kuratierte Übersicht (historischer Stand seit G4), das überführte Relevanzurteil `metadata/curation.json`, Zitationsdaten, Manifest und die append-only Protokolle. `data/canonical/`, `data/index/` und die Qualitätsberichte bleiben bewusst draußen – sie entstehen beim nächsten Ingest deterministisch neu ([ADR 0027](../docs/adr/0027-corpus-backup-phase11.md)). Der Lauf ist **idempotent** (unveränderte Dateien werden über sha256 übersprungen), `--dry-run` schreibt nichts, `--pruefen` rechnet einen vorhandenen Stand gegen sein Manifest nach (Exit `1` bei Abweichung). Aufruf: `python -m scripts.backup --ziel <Pfad> [--dry-run] [--pruefen]`. |
| `qa.py` | QS-Harness: spielt das feste Prüf-Fragen-Set je erwartetem Modus (Basic/Local/Global/DRIFT) durch und zeigt die belegte Provenienz ([ADR 0010](../docs/adr/0010-drop-in-workflow-and-qa-phase6.md)). Mit `--quantitativ` folgt der Regressions-Check gegen die eingefrorene Baseline ([ADR 0016](../docs/adr/0016-quantitative-retrieval-evaluation-phase7.md)). Aufruf: `python -m scripts.qa [--quantitativ]`. |
| `eval_retrieval.py` | Quantitative Retrieval-Evaluation gegen das versionierte Gold-Set [`eval/retrieval-gold.json`](../eval/retrieval-gold.json), dessen Labels mechanisch aus dem Chunk-Text abgeleitet sind. Ohne Schalter wird die geteilte **Chunk-Primitive** gemessen (Hit@k/MRR, schnell); `--modi` misst die **Modi als Ganzes** inklusive Local-Baustein-Beitrag, Community-Coverage mit Trivial-Baselines und DRIFT-Deckelung (langsam). `--scoring` vergleicht die Wertungen, `--verify-labels` rechnet die Labels gegen den Index nach, `--write-gold` leitet sie nach einem Korpuswechsel **neu ab** (Fragen bleiben unverändert; `--gold-version` und `--notiz` beschriften den Stand, eine Frage ohne Ziel meldet Exit `1`), `--write-baseline`/`--check` frieren den Stand ein bzw. melden Regressionen **qid-genau** – Exit-Codes `0` unauffällig, `1` Befund, `2` Baseline nicht vergleichbar ([ADR 0014](../docs/adr/0014-hybrid-retrieval-bm25-tfidf-phase7.md), [ADR 0016](../docs/adr/0016-quantitative-retrieval-evaluation-phase7.md)). Mit `--router` wird stattdessen die **Contract-Treue des Query-Routers** gegen [`eval/router-gold.json`](../eval/router-gold.json) gemessen (ohne Index, sofort); `--router --verify-labels` prüft die abgeleiteten Labels und die Signal-Abdeckung ([ADR 0017](../docs/adr/0017-router-hardening-phase7.md)). Mit `--zitationen` wird die **Multi-Hop-Ebene** gegen [`eval/citation-gold.json`](../eval/citation-gold.json) gemessen: fünf Ebenen (strukturell plus je zwei Anfrageformen für Basic und Local), Labels aus den `CITES`-Kanten, eigene Baseline [`eval/citation-baseline.json`](../eval/citation-baseline.json); `--zitationen --write-gold` erzeugt das Gold-Set aus dem Index neu ([ADR 0023](../docs/adr/0023-multihop-citation-evaluation-phase10.md)). Aufruf: `python -m scripts.eval_retrieval [--k …] [--scoring …] [--modi] [--check] [--router] [--zitationen]`. |

Damit `python -m scripts.…` funktioniert, enthält der Ordner ein `__init__.py`.

Eine ausführliche Bedienanleitung zu `discover.py` (Proxy einrichten, Anfrage wählen, Bericht
lesen, Vorschlag übernehmen, Fehlerdiagnose) steht in
[docs/online-recherche.md](../docs/online-recherche.md).
